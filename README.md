# 🛡️ 不審サイト収集・レビュー支援システム

公開情報から不審なURL候補を集め、人が確認しやすい形に整理するデスクトップアプリです。フィッシングサイト、詐欺通販、違法商品販売、コピー商品販売の疑いがあるサイトを対象にしています。

自動判定だけで通報することはありません。CSVはレビュー状態に関係なく全候補を保存できます。Excelレポートは、人が確認した候補を出力します。

## 🚀 はじめに

パソコン操作に慣れていない方は、上から順番に進めてください。Supabaseの接続先は管理者が設定済みのため、利用者がURLやAPIキーを設定する必要はありません。

| 必要なもの | 料金 | 用途 |
|---|---|---|
| Python 3.10以上 | 無料 | このアプリを動かすためのソフト |
| urlscan.io APIキー | 無料枠あり | 不審なサイトを安全な外部環境で確認するための鍵 |
| 管理者から発行されたログイン情報 | 無料 | 共通の検出履歴と学習モデルを安全に使うため |
| Gemini APIキー | 任意 | AI補助分析を使う場合だけ必要 |

## 🪟 Windowsで使う場合

### 手順1: Pythonをインストールする

Pythonが入っていない場合は、[Python公式ダウンロードページ](https://www.python.org/downloads/windows/)からインストールしてください。

1. ダウンロードしたインストーラーを開きます。
2. インストール画面に「Add Python to PATH」が表示された場合は、必ずチェックを付けます。
3. インストールを完了します。

すでにPythonが入っているか分からない場合でも、次の`start.bat`が確認してくれます。

### 手順2: アプリを起動する

1. このプロジェクトのフォルダーを開きます。
2. `start.bat`をダブルクリックします。
3. 初回は`.env`と必要なライブラリが自動で準備されます。
4. アプリ画面が開いたら、APIキーと管理者から通知されたログイン情報を入力します。

初回起動はライブラリをインストールするため、数分かかる場合があります。

## 🐧 Linuxで使う場合

### 手順1: Pythonを確認する

ターミナルを開き、次を実行します。

```bash
python3 --version
```

`Python 3.10`以上が表示されれば準備済みです。Pythonがない場合、UbuntuまたはDebianでは次を実行します。

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
```

その他のLinuxでは、各ディストリビューションのパッケージ管理機能を使うか、[Python公式ダウンロードページ](https://www.python.org/downloads/)を確認してください。

### 手順2: アプリを起動する

プロジェクトのフォルダーで、次を実行します。

```bash
chmod +x start.sh
./start.sh
```

初回は`.env`と必要なライブラリが自動で準備され、そのままアプリ画面が開きます。

## 🔑 初回に必要なサービス設定

### 1. urlscan.io APIキー

urlscan.ioを利用するための、自分専用の文字列です。パスワードに近い役割があるため、他人へ見せないでください。

1. [urlscan.ioアカウント作成ページ](https://urlscan.io/user/signup)を開きます。
2. アカウントを作成し、メール確認を済ませてログインします。
3. urlscan.ioの利用者ページでAPIキーを確認します。
4. 表示されたAPIキーを、アプリの「urlscan.io API キー」欄へ貼り付けます。

詳しい仕様は[urlscan.io公式API説明](https://urlscan.io/docs/api/)で確認できます。

> ⚠️ APIキーをREADME、ソースコード、共有画面へ貼り付けないでください。

### 2. 管理者からSupabaseログイン情報を受け取る

Supabaseは、「すでに調べたURL」「人が確認した結果」「共有学習モデル」を全利用者で共有する保存場所です。

利用できるのは、管理者が事前登録した信頼できる人だけです。管理者から次の2つを受け取ってください。

- このアプリ専用のログインメールアドレス
- このアプリ専用のログインパスワード

Supabase管理画面のアカウントやDatabase Passwordとは別物です。Project URLとPublishable keyはアプリに共通設定されているため、利用者には不要です。

### 3. Gemini APIキーは必要な場合だけ取得する

Gemini補助分析を使わない場合、この設定は不要です。使う場合は[Google AI Studio](https://aistudio.google.com/app/apikey)でAPIキーを作成し、アプリの「Gemini API キー」欄へ貼り付けます。

> ⚠️ Gemini APIキーも他人へ見せず、GitHubやREADMEへ書かないでください。

## 📝 アプリ画面へ入力する内容

アプリ左側の設定欄へ、次の5項目を入力します。

### 1. urlscan.io APIキー

- 入れるもの: urlscan.ioで取得した長い文字列
- 入手場所: [urlscan.ioアカウント作成ページ](https://urlscan.io/user/signup)
- 役割: urlscan.ioの検索やスキャン機能を利用する
- 注意: 他人へ見せない。GitHubやREADMEへ書かない

### 2. Supabase利用者のメールアドレスとパスワード

- 入れるもの: 管理者から通知された、このアプリ専用のメールアドレスとパスワード
- 役割: 許可された利用者かを確認し、レビュー担当者を監査履歴へ残す
- 間違いやすい点: Supabase管理画面へログインするアカウントや、プロジェクト作成時のDatabase Passwordとは別のもの

利用者同士で同じパスワードを共有せず、必ず一人ずつ別のアカウントを使ってください。

### 3. 報告者の氏名

- 入れるもの: 検出結果を確認する人の氏名
- 入力例: `山田 太郎`
- 役割: Excelレポートの氏名欄と、人手レビューの担当者欄へ記録する

アカウント名ではありません。実際に内容を確認する担当者名を入力してください。

### 4. Excelテンプレート

- 入れるもの: 結果を書き込む元のExcelファイル
- 既定値: `テンプレート/CYCOTサイパト実施結果（京都テック、氏名欄あり）_.xlsx`
- 選び方: 「テンプレートを選択」を押し、`.xlsx`、`.xlsm`、または`.xls`ファイルを選ぶ

通常は最初から入っているテンプレートをそのまま使えます。ここには保存先フォルダーを指定しないでください。

### 5. 検出結果の保存先

- 入れるもの: 完成したExcelやCSVを保存するフォルダー
- 既定値: `検出結果/`
- 選び方: 「保存先を選択」を押し、書き込み可能なフォルダーを選ぶ

ここではファイルではなくフォルダーを選びます。元のExcelテンプレートが入っている`テンプレート/`とは別のフォルダーを選んでください。

すべて入力したら「認証情報を安全に保存」を押します。APIキーとパスワードは`.env`へ平文保存せず、OSの資格情報マネージャーへ保存されます。

## ▶️ 基本的な使い方

### 1. 監視を始める

「監視開始」を押します。初めて使う場合は、任意機能を変更せず、そのまま開始してください。

処理中は、リアルタイムログ、検出候補、API使用状況、自動学習の状態を画面で確認できます。途中で止める場合は「停止」を押します。

### 2. 検出結果を人が確認する

「検出一覧」タブを開き、URL、分類、優先度、根拠を確認します。不審なサイトを直接開かず、表示された根拠とurlscan.ioの参照結果を使って確認してください。

対象行を選び、レビュー状態と理由を入力して「状態を更新」を押します。レビューはCSV保存の前後を問わず、必要なときに行えます。

| 状態 | 使い方 |
|---|---|
| 🔍 調査中 | まだ確認を続ける |
| ✅ 問題なし | 正常または対象外と確認した |
| ⚠️ 疑いが強い | 複数の根拠から不審と確認した |
| ❓ 判定不能 | 根拠が足りず判断できない |
| 📄 資料作成済み | 提出用資料を作成できる状態 |
| ✔️ 対応確認済み | 対応結果を確認した |

レビューを行う際は理由が必須です。Excelレポートは「疑いが強い」または「資料作成済み」にした候補だけが出力の対象になります。CSV保存にレビューは不要です。

### 3. ExcelまたはCSVへ保存する

- Excelを作る場合は「Excelレポートを保存」を押します。
- CSVを作る場合は「CSVエクスポート」を押します。未レビューを含む全候補と、保存時点のレビュー状態・理由が出力されます。保存後にレビューした内容を反映するには、再度CSVを保存してください。
- URL履歴をExcelへまとめる場合は、リアルタイムログ画面の「URLログをExcelで保存」を押します。

保存画面は、設定した`検出結果`フォルダーから開きます。Excelはテンプレートの書式を維持し、最初の空き行へ結果を追加します。元のテンプレートへ上書きすることはできません。

出力ファイルと同じ場所には、改変確認用の`.manifest.json`も作成されます。出力対象がない場合は案内が表示されます。

## ⚙️ 任意機能

設定名へカーソルを合わせると、画面上でも説明が表示されます。

| 機能 | 既定値 | 内容 |
|---|---:|---|
| CT監視 | 無効 | 新しく発行された証明書から候補を探す。候補数と通信量が増える |
| 新規urlscan送信 | 無効 | 既存結果がないURLをurlscan.ioへ送る。API利用枠を消費する |
| Gemini補助分析 | 無効 | 取得済み情報をAIで補助分析する。Gemini APIキーが必要 |
| 自動学習 | 有効 | 人が確定したレビューから学習する。自動通報はしない |

初めて使う場合は、CT監視、新規urlscan送信、Gemini補助分析を無効のままにすることを推奨します。

## 🧠 自動学習の使い方

自動学習は、許可された全利用者が確定したレビューを共通の教師データとして使います。アプリ自身の予測を正解として学習することはありません。

1. 検出結果を人が確認します。
2. 正常な候補を「問題なし」にします。
3. 不審と確認した候補を「疑いが強い」または「資料作成済み」にします。
4. 陽性例と陰性例がそれぞれ20件に達すると、学習と評価が始まります。
5. 評価基準を満たしたモデルだけが共通モデルとして保存され、全利用者の次回の監視から使われます。

最初に「教師データ収集中」や「例待ち」と表示されるのは正常です。誤検知を減らすため、不審な例だけでなく「問題なし」の例も登録してください。

同時に複数人が学習しても、古いモデルを基にした結果で新しいモデルを上書きしないよう競合を検出します。誰が登録したレビューかは監査履歴に残ります。

自動学習は候補を探すための補助機能です。モデルだけで通報、違法性の確定、レポート確定は行いません。

## 📋 URL履歴ログ

監視を開始すると、`logs`フォルダーへ監査用ログと、人が確認しやすいCSVログが自動作成されます。

| ファイル | 内容 |
|---|---|
| `logs/filter_passed_urls.csv` | 収集フィルタを通過したURL。Excelで閲覧する人向け |
| `logs/scanned_urls.csv` | 重複排除後、スキャン処理へ渡したURL。Excelで閲覧する人向け |
| `logs/filter_passed_urls.log` | フィルタ通過履歴のJSON監査ログ |
| `logs/scanned_urls.log` | スキャン開始履歴のJSON監査ログ |

CSVには日本語の見出しが付き、日時、処理、URL、ドメイン、収集元、候補分類、スコアが列ごとに表示されます。`.csv`をExcelで開くか、リアルタイムログ画面の「URLログをExcelで保存」を押すと、2種類の履歴を分けたExcelファイルを作成できます。

`.log`は1行につき1件のJSON形式で追記される機械処理・監査向けファイルです。どちらの形式にも、URLのクエリ文字列、フラグメント、ユーザー名、パスワードは保存されません。

監視中にCSVをExcelで開くと追記できない場合があります。確認後はExcelを閉じてください。CSVがロックされても、監査用`.log`への記録は継続します。

2つのログの件数が違う場合があります。重複排除、キュー上限、最大スキャン数、停止操作などによって、フィルタを通過したすべてのURLがスキャンされるとは限らないためです。

## 🧰 エラーが発生した場合

### Supabaseへ接続できない

- 管理者から通知されたメールアドレスとパスワードか確認する
- 「共通Supabase: 接続設定済み」と表示されているか確認する
- 「許可一覧にありません」と出る場合は、管理者へ事前登録を依頼する
- 管理者は4つのSQLが適用済みか確認する

### API制限エラーが出る

画面のAPI使用状況で残量と待機時間を確認してください。一時的なエラーは自動で再試行され、HTTP 429の場合はクールダウン状態が表示されます。

### GeminiのJSONエラーが出る

アプリが応答の修復と別モデルでの再生成を試します。それでも失敗した場合はGeminiの結果を使わず、取得済みの根拠と通常ルールで処理を続けます。

### Excelへ書き込めない

- 正しいテンプレートを選択したか確認する
- 出力先のExcelファイルを閉じる
- 対象を「疑いが強い」または「資料作成済み」にする
- テンプレートと検出結果の保存先が別か確認する

## 🔧 詳しい設定

主な設定は`.env`で変更できます。通常は既定値のままで使用できます。

| 変数 | 既定値 | 内容 |
|---|---:|---|
| `MAX_SCAN_COUNT` | `50` | 1回の最大スキャン数 |
| `QUEUE_SIZE` | `500` | 候補キューの上限 |
| `SCAN_WORKERS` | `4` | 同時処理数 |
| `PHISHING_FEED_ENABLED` | `true` | OpenPhishから候補を収集 |
| `CT_ENABLED` | `false` | CT監視 |
| `URLSCAN_SUBMISSION_ENABLED` | `false` | 新規urlscan送信 |
| `LLM_ENABLED` | `false` | Gemini補助分析 |
| `AUTOMATIC_LEARNING_ENABLED` | `true` | 自動学習 |
| `LEARNING_MINIMUM_PER_CLASS` | `20` | 学習に必要な陽性・陰性の最低件数 |

`AUTOMATIC_REPORTING_ENABLED`は常に`false`にしてください。`true`にすると安全のため起動が拒否されます。

## ⚠️ 安全上の注意

- 検出結果を犯罪や違法性の確定判断として扱わないでください。
- 通報や提出の前に、対象、証拠、利用規約、法令を人が確認してください。
- 候補サイトへ直接アクセスしたり、購入、接触、攻撃を行ったりしないでください。
- APIキー、利用者情報、収集データを安全に管理してください。
- 外部サービスの利用規約とレート制限を守ってください。

## 💻 開発者向け情報

仮想環境を準備済みの場合は、次のコマンドでも起動できます。

Windows:

```powershell
.\venv\Scripts\python.exe src\main.py
```

macOSまたはLinux:

```bash
./venv/bin/python src/main.py
```

テスト:

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe -m compileall -q src tests
```

主なフォルダーは次のとおりです。

```text
src/                  アプリ本体
tests/                自動テスト
supabase/migrations/  Supabase用SQL
config/                管理者が設定する共通接続先
data/                 判定用データ
テンプレート/          Excelテンプレート
検出結果/              ExcelとCSVの出力先
logs/                 URL履歴ログ
```

## 🛠️ 管理者向け: 共通Supabaseの初期設定

この作業は配布する管理者が1回だけ行います。一般利用者にはSupabaseのProject URLやPublishable keyを設定させません。

1. [Supabase Dashboard](https://supabase.com/dashboard)で、このアプリ専用のプロジェクトを用意します。
2. Supabase DashboardのAuthentication設定で、一般利用者による新規登録を無効にします。
3. SQL Editorで次の4ファイルを上から順番に実行します。

   1. `supabase/migrations/202609020001_detection_schema.sql`
   2. `supabase/migrations/202609030001_spec_v11_history.sql`
   3. `supabase/migrations/202609030002_online_learning.sql`
   4. `supabase/migrations/202609060001_shared_trusted_learning.sql`

4. `config/shared_backend.json`へProject URLと`sb_publishable_`で始まるPublishable keyを記入します。確認場所は[Supabase公式APIキー説明](https://supabase.com/docs/guides/getting-started/api-keys)を参照してください。
5. AuthenticationのUsersで、利用者ごとに別のメールアドレスとパスワードを作成します。詳しくは[Supabase公式の利用者説明](https://supabase.com/docs/guides/auth/users)を参照してください。
6. 作成した利用者のUUIDを、SQL Editorで許可一覧へ追加します。

```sql
insert into private.trusted_app_users (user_id, display_name)
select id, '担当者名'
from auth.users
where email = 'user@example.com'
on conflict (user_id) do update
set display_name = excluded.display_name, active = true;
```

利用停止だけを行う場合は、履歴を保つためAuth利用者をすぐ削除せず、まず次を実行します。

```sql
update private.trusted_app_users
set active = false
where user_id = (select id from auth.users where email = 'user@example.com');
```

`sb_secret_`で始まるSecret key、service_roleキー、Database Passwordは配布物へ絶対に入れないでください。既存のAuth利用者は4番目のSQLを初めて適用した時点で許可一覧へ自動登録されます。それ以降に作る利用者は手順6が必要です。
